# Art direction

Stylized 3D, mid-poly, readable at two distances: a colonist at about 4 m of camera distance, and a holding from about 40 m up. Big shapes. Few tiny surface details. Stylized PBR.

The camera is isometric. Q and E snap it in 90 degree steps. Design buildings so each snap still explains the door, the roof, and the work spot.

## Light and sky

Cinderwell is a warm orange key. Shadows are cool. Dusks are long, and the clock in the sim drives the sun, because night changes temperature and who is awake.

The Stitch is always faintly in the skybox. A screenshot should tell you the ring fell without a caption.

## Shared material rules

- One accent color per people, used on cloth, trim, or a light. The race doc names it.
- Injury is a decal, a limp, and a UI clock. Gore is not the style.
- Placeholder art is how a milestone finishes. A tinted blockout with the right silhouette is better than a stall for a finished mesh.
- Generated concept images, when they exist, live in `docs/art-ref/` and are reference only. Do not import them as runtime textures by accident.

## Animation

The first set is idle, walk, work, hit, and down. The Harth get it first. Every other people reuses that skeleton. Crests, membranes, coats, grafts, veils, and bark are props on the silhouette until a people is promoted to a unique set.

## What to draw first, per people

When a people is promoted out of blockout, the set is:

1. A turnaround of one default body, using the measurements in the race doc
2. One holding exterior in their material language
3. One prop from their starting kit

The race doc is the authority for palette, architecture, and default body. This file is the authority for camera readability, light, and production order.

## Biomes, as color

So the eye can sort the map before the UI does:

| Biome | Ground | Sky influence | Landmark |
| --- | --- | --- | --- |
| Temperate valley | Ochre soil, green crop, dark timber | Warm haze | The peg and a ditch |
| Glass basin | Charcoal glass, copper glints | Heat shimmer | A kiln arch |
| Coast | Teal water, brass, pale sand | Bright, wet | A bridge or a coracle |
| Karst | Bone stone, ink shadow, amber lamp | Dim | A ribbed entrance |
| Mesa | Sand and sky-bleach | Hard clear light | A sail frame |
| Marsh | Wet brown, violet fog, spore gold | Low contrast | A gauze banner |
| Hull crater | Cobalt, rust, warning yellow | Dust | A bulkhead in the dirt |

## Readability checklist

- Selected people carry a ground ring and a job icon.
- A drafted person reads differently from a working person at holding zoom.
- An order shows a path and a destination marker until the job ends or fails.
- A failed job says why, in one line: hungry, no path, no station, no skill, no material, afraid, night.
- Two peoples standing together are distinguishable with the color and the silhouette alone, even before faces exist.

## How an asset gets made

A box, a cylinder, or a tinted blockout stays a Godot primitive in GDScript. Placeholder art is how a milestone finishes. A mesh whose silhouette a primitive cannot carry is generated by scripted Blender, imported once, and then loaded like any other scene.

The generator is `scripts/gen_<name>.py`. Run it only through `scripts/asset-spike.sh <name>`, from the repository root. That runs Blender headless and writes `godot/assets/<name>.glb`. The example is a storage barrel, `scripts/gen_barrel.py`: dark timber staves and two soot hoops, 0.72 m tall, 0.56 m across the belly. Timber and soot are the temperate-valley material language. The people's accent color is not on the prop. One accent, on cloth, trim, or a light.

Measured with no display, no X server, and no GPU driver. Blender from nixpkgs is 5.2.2. The command is:

`nix shell nixpkgs#blender -c blender --background --factory-startup --python <generator> -- <out.glb>`

`scripts/asset-spike.sh barrel` is that command. It printed `BLENDER_VERSION 5.2.2 LTS` and `Blender 5.2.2 LTS`, wrote `godot/assets/barrel.glb` (13012 bytes; 158 Blender vertices, 120 faces, 2 materials), and exited 0 in 2.149 s. The glTF export itself was 0.0155 s. The same invocation, pointed at a one-cube generator, exited 0 in 2.233 s and wrote a 1420-byte glb. Neither log mentioned the display, the GPU, or EGL. The file is glTF 2.0, generator string `Khronos glTF Blender I/O v5.2.40`, no extensions, Draco not used. The barrel stands on Y after export (height 0.72, radius 0.28).

The one error line was audio, and the export still exited 0:

`[ALSOFT] (EE) Failed to connect PipeWire event context (errno: 112)`

A game run does not import a new `.glb`. Before the import pass, `load` on `res://assets/barrel.glb` returned null, `ResourceLoader.exists` was false, the engine logged `ERROR: No loader found for resource: res://assets/barrel.glb`, and the process exited 2. No `.import` file was written.

The import that works, from the repository root, in the devshell:

`godot --headless --path godot --import`

That pass imported `barrel.glb` and finished editor layout in 4.733 s, exit 0. No display, GPU, or EGL error. The exit code is not the gate. The load is. After the import, a headless game run loaded a `PackedScene`. The mesh node was an `ArrayMesh` with 2 surfaces: 314 vertices, material Timber, albedo `(0.68, 0.5469, 0.3959, 1.0)`; 96 vertices, material Soot, albedo `(0.3318, 0.3133, 0.2934, 1.0)`; 410 vertices total. AABB position `(-0.28, 0.0, -0.28)`, size `(0.56, 0.72, 0.56)`, standing on Y. The 410 is the glTF vertex count, not Blender's 158: flat normals split vertices. The albedo numbers are the sRGB reading of the linear factors written into the file (timber `0.42, 0.26, 0.13`, soot `0.09, 0.08, 0.07`). The rendered color matched the timber and the soot, so that conversion is not a failed import.

A frame needs a display and software Vulkan. `--headless` is not a frame path. `scripts/render.sh` is the recipe: Xvfb, lavapipe, Forward+. It takes a scene, and the scene has to honour `LATCHSOIL_SCREENSHOT`. Calling the script as a program was exit 126, permission denied. This is what ran, and it exited 0 in 9.586 s:

`bash scripts/render.sh <scene> <out.png> 1280 720`

The engine logged `Vulkan 1.4.354 - Forward+ - Using Device #0: Unknown - llvmpipe (LLVM 21.1.8, 256 bits)` and wrote a 1280×720 PNG. The picture was a faceted timber barrel with two dark hoops, standing on an ochre plane against a dark background. The silhouette reads as a barrel at about 4 m of camera distance. The same scene under `godot --headless`, with `LATCHSOIL_SCREENSHOT` set, wrote no PNG and did not exit within 180 s.

What does not work, from these runs:

- Do not wait on a display, a GPU driver, or an X server for the Blender export. The PipeWire line is noise.
- Dropping a `.glb` into the project does not make it loadable. The game run will not import it.
- `--headless` did not produce a frame. Use `bash scripts/render.sh`.
- The import exit code is not the proof. This run exited 0 after layout finished. Proof is the load: surface count, vertex count, AABB. A non-zero exit from that pass is not, by itself, a failed import.
- Draco was not in the file this exporter wrote, and a Draco file was not tested. Leave compression off.
- The `.glb` is generated output, not source. It is not in the tree until the script is run, and a game run still cannot load it until the import pass above.

Keep a mesh in GDScript primitives while its job is a silhouette and a tint. Placeholder art finishes a milestone, big shapes beat tiny surface detail, a holding has to read at about 40 m, and two peoples have to separate by color and silhouette before faces exist. A box and a cylinder already do that, and a 0.72 m barrel at 40 m is a speck either way. Move a mesh to scripted Blender when a people is promoted out of blockout and the 4 m read is a specific shape a primitive cannot carry. The barrel's belly and two hoops are that case, and the frame at about 4 m showed them. The measured cost is 2.149 s of headless Blender with no display and no GPU, one import pass of 4.733 s before a game run can load the file, and a software-Vulkan frame in 9.586 s. That is cheap enough to script, and not a reason to stall a milestone waiting for it. The barrel used timber and soot, not the people's accent: one accent, on cloth, trim, or a light. It is a prop, not a skeleton. The first animation set is idle, walk, work, hit, and down, and every other people reuses that skeleton. Crests, membranes, coats, grafts, veils, and bark stay props on it until a people is promoted to a unique set. Do not send those through Blender as a second rig.
